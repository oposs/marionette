**ModalSurface.svelte -- Replace custom overlay with shadcn Dialog (per D-03, Pitfall 2):**
- Import `* as Dialog` from `$lib/components/ui/dialog`
- Remove the entire custom `<div class="fixed inset-0 ...">` overlay structure and the a11y ignore comments
- Replace with:
  ```svelte
  <Dialog.Root open={isOpen} onOpenChange={(open) => { if (!open) handleClose(); }}>
    <Dialog.Content class="sm:max-w-lg">
      {#if tree}
        <NodeRenderer nodeId={tree.root} nodes={tree.nodes} surface="modal" />
      {/if}
    </Dialog.Content>
  </Dialog.Root>
  ```
- Keep existing `handleClose()` that calls `sendAction('close-modal')` exactly as-is
- Keep existing derived `tree` and `isOpen` logic exactly as-is
- CRITICAL (Pitfall 2): Use `open={isOpen}` (one-way bind from SDUI) -- never let Dialog manage its own state. The `onOpenChange` callback only dispatches the close action; the actual open state is derived from surface tree existence.

**ConfirmDialog.svelte -- Use shadcn Dialog + Button composable (per D-03):**
- Import `* as Dialog` from `$lib/components/ui/dialog`
- Import `{ Button as ShadcnButton }` from `$lib/components/ui/button`
- ConfirmDialog is always rendered inside ModalSurface's Dialog.Content (it's a child node). So ConfirmDialog itself does NOT render a Dialog.Root -- it renders Dialog sub-components for structure.
- Replace the current `<div class="p-4">` with:
  ```svelte
  <div>
    <Dialog.Header>
      {#if title}
        <Dialog.Title>{title}</Dialog.Title>
      {/if}
      {#if message}
        <Dialog.Description>{message}</Dialog.Description>
      {/if}
    </Dialog.Header>
    <Dialog.Footer>
      <ShadcnButton variant="outline" onclick={handleCancel}>
        {cancelLabel}
      </ShadcnButton>
      <ShadcnButton variant={destructive ? 'destructive' : 'default'} onclick={handleConfirm}>
        {confirmLabel}
      </ShadcnButton>
    </Dialog.Footer>
  </div>
  ```
- Title: Dialog.Title renders 20px semibold per UI-SPEC
- Description: Dialog.Description renders 14px `text-muted-foreground` per UI-SPEC
- Footer: right-aligned with 8px gap (shadcn Dialog.Footer has `flex justify-end gap-2` by default)
- Keep ALL existing handleConfirm/handleCancel logic
- Note per UI-SPEC: cancelLabel comes from server via `props.cancelLabel` -- no hardcoded default "Cancel"

**ToastSurface.svelte -- Keep custom, update styling (per D-04 / Research Open Question 1):**
- Per the research finding: bits-ui has no toast primitive, and shadcn-svelte's toast IS Sonner. The user decision D-04 said "shadcn Toast" but that doesn't exist as described. Research recommends keeping the current custom SDUI-driven ToastSurface and updating styling to use semantic tokens.
- Remove the `severityClass` record that uses hardcoded colors (`border-green-500/30 bg-green-50 text-green-800`, `border-yellow-500/30 bg-yellow-50 text-yellow-800`)
- Replace with semantic token classes:
  ```typescript
  const severityClass: Record<string, string> = {
    success: 'border-primary/30 bg-primary/10 text-foreground',
    error: 'border-destructive/30 bg-destructive/10 text-destructive',
    warning: 'border-yellow-500/30 bg-yellow-50 text-foreground dark:bg-yellow-950 dark:text-foreground',
    info: 'border-border bg-card text-foreground',
  };
  ```
  Note: warning severity has no direct semantic token equivalent. Use bg-card for info (per UI-SPEC Toast card: `bg-card border-border`). For error variant, use `border-destructive` left accent per UI-SPEC.
- Update position from `fixed top-4 left-4 right-4 md:left-auto` to `fixed bottom-4 right-4` per UI-SPEC (bottom-right corner, 16px from edges)
- Update container: `class="fixed bottom-4 right-4 z-[60] flex flex-col gap-2 max-w-sm"`
- Toast card: add `shadow-lg` per UI-SPEC
- Close button: replace `&times;` with lucide X icon: import `X` from `@lucide/svelte/icons/x`, render `<X class="size-4" />`
- Keep existing `addToast()` export function and `removeToast()` logic
- Keep `fly` transition for animation
