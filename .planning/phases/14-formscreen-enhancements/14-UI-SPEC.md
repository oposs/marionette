# Phase 14 — UI Design Contract

> Visual and interaction contract for FormScreen enhancements. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Inherits and extends the Phase 10 foundation tokens and the Phase 11 leaf-component contract. Phase 14 is additive: it introduces the shadcn-svelte `Field` family as the canonical anatomy for every form leaf, adds a structural `FieldSet` grouping primitive with an auto-responsive grid, and introduces three new leaf primitives (`Textarea`, `RadioGroup`, `Switch`). It does NOT change any global design token, color role, or typography scale. All upstream locks from `14-CONTEXT.md` (D-A1 through D-E5) apply verbatim and are treated as the design contract.

## Spacing Scale

Declared values (must be multiples of 4). Inherited from Phase 11 UI-SPEC.

| Token | Value | Usage in Phase 14 |
|-------|-------|-------------------|
| xs | 4px (0.25rem) | Reserved; not newly applied in Phase 14 |
| sm | 8px (0.5rem) | Vertical gap inside a single `Field.Field` (label → control → description/error), gap between action-row buttons |
| md | 16px (1rem) | `Field.Group` grid `gap-4` between sibling fields; `Form` children vertical rhythm |
| lg | 24px (1.5rem) | Vertical rhythm between sibling `FieldSet`s (`space-y-6` on `Form` children) |
| xl | 32px (2rem) | Reserved for page-level layout (managed by AppShell/Container outside this phase) |
| 2xl | 48px (3rem) | Not used in Phase 14 |
| 3xl | 64px (4rem) | Not used in Phase 14 |

**Phase 14 authoritative spacing rules:**

1. `Field.Group` inside `FieldSet`: `grid grid-cols-1 md:grid-cols-2 gap-4` — 16px gap between fields both horizontally and vertically (D-C3).
2. `FieldSet.cols=N` override: replaces the grid class with a static `grid gap-4` + inline `grid-template-columns: repeat(N, minmax(0, 1fr))` (Pitfall #1 — Tailwind v4 cannot JIT dynamic `grid-cols-{N}`).
3. Per-field `full_width=true` override: adds `col-span-full` to that field's `Field.Field` wrapper (D-C4). No custom spacing, just full-row span.
4. Sibling `FieldSet` vertical separation: 24px (`space-y-6`) applied on the direct children slot of `Form.svelte` (wrapping children in a `Field.Group` per CONTEXT.md D-A3). An explicit `FieldSeparator` SDUI node sitting between two sibling `FieldSet`s renders a `Field.Separator` line within that 24px rhythm (D-C2, preferred explicit-node path).
5. Action row (D-D1): `gap-2` (8px) between buttons, right-aligned via `justify-end`. Implementation is Claude's discretion between a plain `Container class="flex gap-2 justify-end"` and a dedicated `FieldRow` SDUI component wrapping `Field.Field orientation="horizontal"`. Either implementation MUST produce the same 8px gap + right alignment.
6. Default button height from shadcn (`h-9` = 36px). Interactive targets (buttons, inputs, select triggers, textarea, switch thumb hit area) retain the Phase 11 minimum of 36px. The `Switch` primitive's control is 20px × 36px by shadcn default; the 36px horizontal dimension satisfies touch-target comfort even though the vertical is 20px.

Exceptions: none introduced by this phase.

## Typography

Inherited from Phase 11. Phase 14 introduces no new sizes or weights; it only maps field anatomy elements onto the existing scale.

| Role | Size | Weight | Line Height | Phase 14 Usage |
|------|------|--------|-------------|----------------|
| Body | 14px (0.875rem) | 400 (regular) | 1.5 (21px) | `Input` value, `Textarea` value, `RadioGroup.Item` label, `Switch` label text |
| Label | 14px (0.875rem) | 600 (semibold) | 1.43 (20px) | `Field.Label` for every leaf; button labels in the action row |
| Legend | 14px (0.875rem) | 600 (semibold) | 1.43 (20px) | `Field.Legend` inside `FieldSet` — shadcn Field recipe defaults `Field.Legend` to `font-medium text-sm`; Marionette OVERRIDES to `font-semibold` to stay consistent with the Phase 11 "no weight 500" rule |
| Heading | 20px (1.25rem) | 600 (semibold) | 1.2 (24px) | Form-screen page heading (composed by handlers via the existing `Heading` SDUI component — not a Phase 14 additions) |
| Small | 12px (0.75rem) | 400 (regular) | 1.33 (16px) | `Field.Description` text; `Field.Error` text; `RadioGroup` per-option description |

**Phase 14 authoritative typography rules:**

1. Two font weights only: 400 (regular) and 600 (semibold). No weight 500 (medium). If a shadcn-generated primitive (`Field.Legend`, `Field.Label`) renders `font-medium`, override to `font-semibold` in the Marionette wrapper (same rule Phase 11 enforced for `Label` and `Button`).
2. `Field.Description` uses `text-muted-foreground text-sm` per shadcn Field recipe, which maps to the "Small" 12px line at 1.33 in the declared scale. When shadcn-generated CSS sets description to `text-sm` (14px), leave it — `text-sm` at `text-muted-foreground` is an acceptable description style as long as the size stays consistent across all leaves. Actual rendered size: 14px (0.875rem) — shadcn default. Treat Phase 14 "Small" as the cap for error/description copy when the leaf wrapper overrides to 12px; otherwise accept 14px muted as shadcn default. Pick ONE and apply consistently across all six leaves (planner decision during execution).
3. `Field.Error` renders in `text-destructive` at the same size as `Field.Description` — the red color is what distinguishes it, not size or weight.
4. Body `line-height: 1.5` applies to `Textarea` content specifically — multi-line text needs the full leading.

## Color

Inherited from Phase 10/11. Phase 14 introduces no new color roles and uses only the existing OKLCH semantic tokens from `frontend/src/app.css`.

| Role | Token | Usage in Phase 14 |
|------|-------|-------------------|
| Dominant (60%) | `--background` / `bg-background` | Form background, `Field.Set` background (no explicit surface) |
| Secondary (30%) | `--card` / `bg-card` | Not directly used in Phase 14 forms (D-C2 rejects `Card.Root` wrapping for FieldSet) |
| Accent (10%) | `--primary` / `bg-primary` | Primary submit button fill; `Switch` checked-state thumb track; `RadioGroup.Item` checked indicator; focus ring on all inputs via `--ring` |
| Destructive | `--destructive` / `text-destructive`, `border-destructive` | `Field.Error` text, `aria-invalid` ring/border on every input when `/_errors/{bind}` is non-empty |
| Muted foreground | `--muted-foreground` / `text-muted-foreground` | `Field.Description` text, disabled text, placeholder |
| Border | `--border` / `border-border` | `Field.Separator` line color, input borders default |
| Input | `--input` / `border-input` | Input/Textarea border (shadcn default) |
| Ring | `--ring` / `ring-ring` | Focus ring on every input control |

**Accent (`--primary`) reserved for:**

- Primary action buttons (Save, Create, Submit — `variant="default"`, dark fill with light text)
- `Switch` checked state (track fill)
- `RadioGroup.Item` checked indicator dot
- Focus ring on inputs, textareas, select triggers, radio items, switches, checkboxes
- (No additional Phase 14 uses — everything else is a muted, border, or destructive role)

**Destructive reserved for:**

- `Field.Error` text below an invalid field
- `aria-invalid` border/ring on the invalid control (automatic via shadcn `aria-invalid:*` utilities in the generated Input/Textarea/Select primitives)
- NOT used for the Cancel button (cancel uses `variant="outline"` or `variant="ghost"`); destructive-variant buttons are reserved for delete/destroy actions, which are out of Phase 14's scope but inherited from Phase 11.

Semantic guarantee: the `data-invalid` attribute on `Field.Field` is present only when `/_errors/{bind}` resolves to a non-empty string. The attribute is OMITTED (`undefined`), never `data-invalid="false"`. The same omission rule applies to `aria-invalid` on the control. This is required by shadcn Field's CSS selector conventions (14-RESEARCH.md Pattern 1 notes).

## Component Visual Contracts

All six form leaves render the same outer anatomy (D-B1). Any deviation below is controlled by the primitive's unique semantics (e.g., `RadioGroup` has no single `<input>`; it has a collection of items).

### Shared Leaf Anatomy

Every form leaf wraps its control in this structure:

```
<Field.Field data-invalid={hasError || undefined} class={full_width ? "col-span-full" : undefined}>
  <Field.Label for={id}>{label}</Field.Label>       // omitted when no label
  <Control id={id} aria-invalid={hasError || undefined} ... />
  <Field.Description>{description}</Field.Description>  // shown only when no error
  <Field.Error>{error}</Field.Error>                // shown only when /_errors/{bind} is non-empty
</Field.Field>
```

- `id` resolves from the component's protocol `props.id`, falling back to `crypto.randomUUID()` at mount (D-B4). Planner MAY use a bind-derived fallback instead of UUID if determined cleaner during execution, provided stability across re-renders is preserved.
- `Field.Description` suppressed while an error is active (shadcn recipe).
- The `full_width` class application happens on the `Field.Field` wrapper, never on the inner control (D-C4).

### TextInput (rewritten)

- Internal `Field.Field` wrap with the shared anatomy.
- Input height: 36px (shadcn `h-9` default).
- `type` attribute sourced EXCLUSIVELY from `props.input_type` (default `'text'`) — D-E1. No fallback to `props.type`.
- Placeholder: `text-muted-foreground`.
- `onblur` handler unchanged in behavior (clearDirty + setData); the unmount-race bug fix (D-E2) lives in `NodeRenderer.svelte` per preference, not in `handleBlur`.

### SelectInput (rewritten)

- Internal `Field.Field` wrap with the shared anatomy.
- Trigger height: 36px matching TextInput.
- Dropdown content: `bg-popover` with `border-border`, 4px border-radius.
- Selected item: `bg-accent` highlight.

### Checkbox (rewritten)

- Internal `Field.Field` wrap. Checkbox uses horizontal orientation: checkbox sits on the same line as its label.
- Layout: `Field.Field` with a flex row containing 16px checkbox + 8px gap + label; `Field.Description` renders below on its own line at 12–14px `text-muted-foreground`.
- Checked fill: `bg-primary` with light check mark.

### Textarea (new, D-E3)

- Internal `Field.Field` wrap with the shared anatomy.
- Default `rows={4}` unless `props.rows` overrides.
- Border and focus treatment mirror `Input` (shadcn-generated `Textarea` primitive under `$lib/components/ui/textarea/`).
- Resizing: `resize-y` default (vertical only); `resize-none` when `props.disabled`.
- `full_width=true` is the expected pattern for long-text fields inside a 2-col `FieldSet`.

### RadioGroup (new, D-E4)

- Internal `Field.Field` wrap. `Field.Label` names the group; control renders a vertical stack of `RadioGroup.Item` entries.
- Each option renders: 16px radio circle + 8px gap + option label (14px semibold 600) + optional 12px `text-muted-foreground` per-option description beneath.
- Checked indicator: `bg-primary` dot inside the radio circle.
- Keyboard navigation and roving-tabindex handled by bits-ui (D-E4 note).
- Backend builder signature: `RadioGroup { label, options: Vec<{value, label, description?}>, description, full_width, disabled }`.

### Switch (new, D-E4)

- Internal `Field.Field` wrap. Horizontal orientation by default: `Field.Label` on the left, `Switch` control on the right, `Field.Description` beneath spanning the full width.
- Control size: shadcn defaults (track ~36×20px).
- Checked track: `bg-primary`; unchecked track: `bg-input`; thumb: white.
- ARIA role: `switch` (handled by bits-ui primitive).
- Backend builder signature: `Switch { label, disabled, description, full_width }`.

### FieldSet (new, D-C1)

- Structural SDUI component `field-set`.
- Renders `<Field.Set>` → optional `<Field.Legend>` → optional `<Field.Description>` → `<Field.Group class={gridClass} style={gridStyle}>{children}</Field.Group>`.
- Default grid: `grid grid-cols-1 md:grid-cols-2 gap-4` (D-C3). Responsive breakpoint `md:` = 768px (Tailwind default). Below 768px: single stacked column.
- `cols=N` override (D-C4): static `grid gap-4` class + inline `grid-template-columns: repeat(N, minmax(0, 1fr))`. The `md:` breakpoint stacking is disabled; the fixed N columns apply at all viewport widths.
- `Field.Legend` uses `font-semibold text-sm` (Phase 14 override from shadcn's `font-medium` default — weight rule).
- Children resolve through `NodeRenderer` (adjacency list), same pattern as `Container`.
- Backend builder signature: `FieldSet { legend, description, cols }`.

### FieldSeparator (new, D-C2 preferred)

- Thin SDUI component `field-separator`.
- Renders `<Field.Separator />` — a 1px border in the current separator token color.
- No props. Used by handlers between sibling `FieldSet` nodes in the adjacency list.
- Rationale: explicit adjacency-list node makes the protocol self-describing and keeps node-patching granular. If planner chooses the alternative (auto-inserted separators in `Form.svelte`), document the heuristic there and do NOT register this component. Preference (and default in this spec): explicit-node path.

### Form (preserved, D-A3)

- Renders `<form onsubmit={trap}>` with dispatched `action` as `ActionMessage`.
- Children wrapped in a `Field.Group` with `space-y-6` (24px vertical rhythm between direct children).
- Form-level errors: when `getData(surface, '/_errors' + form_bind)` resolves to a non-empty array, render a banner ABOVE children. Banner styling:
  - `bg-destructive/10 border border-destructive/50 text-destructive rounded-md p-4 mb-4`
  - 14px regular text
  - Each error message on its own line
- No API or behavioral change beyond the internal class wrap.

### Action Row (D-D1 — Claude's Discretion)

Two acceptable implementations. Both MUST produce identical visual output:

- **Option A (preferred, lower surface):** Plain `Container` with `class="flex gap-2 justify-end"` and `Button` children. Uses existing `Container` SDUI component. No protocol additions.
- **Option B (recipe-faithful):** New `FieldRow` SDUI component (`field-row`) wrapping `<Field.Field orientation="horizontal" class="justify-end">{children}</Field.Field>`. Requires a new backend builder + registry entry.

Visual contract (both options):

- Flex row, 8px (`gap-2`) between buttons, right-aligned (`justify-end`).
- Sits as the last child of `Form.svelte`, separated from the preceding `FieldSet` by the 24px `space-y-6` rhythm.
- Primary CTA (`variant="default"`) is the RIGHTMOST button; Cancel (`variant="outline"`) sits to its left.
- Buttons inherit the Phase 11 Button contract (36px height, 14px label, icon + 8px gap, etc.).

Choose Option A unless Phase 14 discovers a concrete reason to introduce `FieldRow` (e.g., recurring action-row pattern needing a shared component). Default to A for minimum surface area.

### NodeRenderer (edited, D-E2)

- No visual change.
- Structural fix: move the destructured `{bind}` prop accessor INSIDE the `{#if node}` branch so Svelte 5 generates a nullish-safe accessor and stops the `TypeError: Cannot read properties of undefined (reading 'bind')` console noise on `TextInput` blur during unmount races.
- Alternative location (TextInput.handleBlur guard) acceptable if the structural fix proves intractable; document whichever path lands.

## Copywriting Contract

Marionette is an SDUI application: almost all copy is server-driven via component props. Phase 14 introduces no new frontend-hardcoded copy. The contract below defines SHAPE and TONE that handler authors must follow — it does not prescribe specific strings for the CRM demo (Phase 15's concern).

| Element | Copy Contract |
|---------|---------------|
| Primary CTA | Verb + noun, server-driven via `props.label`. Sentence case. Examples: "Save contact", "Create company", "Update user". Never "OK" or "Submit" — always name the noun. |
| Secondary CTA | Verb-led, server-driven. Examples: "Cancel", "Go back", "Discard changes". Cancel verbs prefer "Cancel" for form abandonment; "Go back" only when navigation is the semantic. |
| Field label | Sentence case, noun or short noun phrase. Server-driven via `props.label`. Examples: "First name", "Email address", "Subscription status". No trailing colon. No abbreviations unless industry-standard (e.g., "ZIP code"). |
| Field description (helper) | Sentence case, ends with a full stop. Server-driven via `props.description`. One sentence preferred. Examples: "We'll never share your email." "Leave blank to keep the current password." Replaces the retired `helperText` prop (D-B3). |
| Field error | Sentence case, ends with a full stop. Server-driven via `/_errors/{bind}` data-store path. Actionable: describe the problem AND hint at the fix. Examples: "Email is required." "Password must be at least 8 characters." "This email is already registered. Try signing in." |
| Form-level error banner | Sentence case, ends with a full stop. Server-driven via `/_errors/{form_bind}` (array). Multiple entries render as separate lines. Examples: "Your changes could not be saved." "Two fields need attention below." |
| Field legend (FieldSet) | Sentence case, short noun phrase. Server-driven via `props.legend`. Examples: "Contact information", "Billing address", "Notification preferences". No trailing punctuation. |
| FieldSet description | Sentence case, ends with a full stop. Server-driven via `props.description`. Optional — omit unless the group genuinely needs explanation. |
| Textarea placeholder | Sentence case, present-tense guidance. Server-driven via `props.placeholder`. Examples: "Add notes about this contact…" "Describe the issue in your own words…". Ellipsis is acceptable. |
| RadioGroup option label | Sentence case. Short noun or noun phrase. Server-driven. Examples: "Email", "SMS", "No notifications". |
| RadioGroup option description | Sentence case, ends with a full stop. Server-driven per-option. Optional. Example: "Receive a weekly digest of updates." |
| Switch label | Sentence case, describes the enabled state. Server-driven. Examples: "Send marketing emails", "Two-factor authentication", "Dark mode". |

**Destructive confirmations** (inherited from Phase 11 ConfirmDialog contract — out of Phase 14 scope but relevant to action-row composition): server-driven via `props.title`, `props.message`, `props.confirmLabel` (verb + noun: "Delete contact"), `props.cancelLabel` ("Keep contact", "Go back"). Phase 14 does not introduce new destructive actions; the action row's Cancel button is NOT a destructive action.

**Frontend-hardcoded copy:** NONE introduced by Phase 14. Connection banner, component error fallback, and dev-only fallback tooltips are inherited from Phase 11 unchanged.

## Interaction Contracts

| Component | Trigger | Behavior |
|-----------|---------|----------|
| TextInput | input / blur | Update bound value via `setData(surface, bind, value)` on input. On blur: `clearDirty`. `/_errors/{bind}` read reactively drives `data-invalid` + `aria-invalid` + `Field.Error` render. |
| SelectInput | value change | Update bound value on `onValueChange`. Error state same pattern. |
| Checkbox | checked change | Update bound value on `onCheckedChange`. Error state same pattern. |
| Textarea | input / blur | Same as TextInput. Error state same pattern. |
| RadioGroup | value change | Update bound value on `onValueChange` of `RadioGroup.Root`. Error state same pattern. |
| Switch | checked change | Update bound value on `onCheckedChange`. Boolean-typed bind. |
| Form | submit | `onsubmit` traps default; dispatches form `action` via `sendAction()`. Enter-to-submit preserved via native `<form>` element. |
| FieldSet | — | Passive structural container. No events. Children rendered via `NodeRenderer`. |
| FieldSeparator | — | Passive visual divider. No events. |
| Action row button | click | Standard Phase 11 `Button` behavior — dispatch `action`. |
| NodeRenderer | node unmount | No-op structurally; destructure access guarded by `{#if node}` branch (D-E2 fix). |

**Focus behavior:**

- Input focus MUST be preserved across unrelated node patches (Phase 12 D-A6 guarantee). Adding `Field.Field` wrappers around existing inputs MUST NOT break this; validated by the existing `focus-preservation` browser test, to be re-run after Phase 14 rewrites land.
- `FieldSet.cols` / per-field `full_width` changes that result in a node patch affecting the field's position MUST NOT remount the input control — the `id` attribute stability (D-B4) is the anchor.
- Inside `RadioGroup`, bits-ui handles roving-tabindex and arrow-key navigation. Phase 14 does not override this.

**Validation flow (unchanged from existing Marionette):**

1. Server renders form with no errors → `/_errors/{bind}` paths are empty or absent.
2. User edits, blurs, submits. `Form.submit` dispatches `action` over WebSocket.
3. Server validates; on failure, responds with a `PatchMessage` writing error messages into `/_errors/{bind}` for invalid fields and/or `/_errors/{form_bind}` for cross-field errors.
4. Leaf components reactively re-render with `data-invalid` + `aria-invalid` + `Field.Error` visible. Form banner appears if form-level errors exist.
5. Next edit on an invalid field clears the specific `/_errors/{bind}` entry (server logic, not frontend). Error state disappears as the server patches the error path empty.

No client-side Zod/Superforms validation. No optimistic UI. No debouncing of error state (server is authoritative).

## Responsive Behavior

| Viewport | Behavior |
|----------|----------|
| `<768px` (below `md:`) | FieldSet children stack vertically in a single column (`grid-cols-1`). Form reads top-to-bottom. Action row stays right-aligned. |
| `≥768px` (md and above) | FieldSet children flow in 2 columns (`md:grid-cols-2`). Per-field `full_width` fields still span the full 2-col row. Action row stays right-aligned. |
| `FieldSet.cols=N` | Fixed N-column grid at all viewport widths. No breakpoint-based stacking. Authors use this to force single-column (`cols=1`) or wider layouts on dense screens (`cols=3`, `cols=4`). |

Breakpoint reference: Tailwind v4 default `md:` = 768px. No container queries (deferred to v2, D-C3).

## Accessibility Contract

- `Field.Label for={id}` MUST match a control's `id` attribute. `id` is handler-supplied via backend builder `.id(...)` or UUID-fallback at mount (D-B4).
- `aria-invalid` is present on the control (not the wrapper) when `/_errors/{bind}` is non-empty. `data-invalid` is present on the `Field.Field` wrapper under the same condition. BOTH are OMITTED (not `"false"`) when no error is present.
- `RadioGroup` uses `role="radiogroup"` via bits-ui; items use `role="radio"`. Arrow-key navigation, space-to-select, roving-tabindex handled by bits-ui.
- `Switch` uses `role="switch"` via bits-ui; space/enter to toggle.
- `FieldSet` renders a native `<fieldset>` with `<legend>` via shadcn `Field.Set` / `Field.Legend` — screen readers announce the legend when focus enters any child field.
- Form submit: enter-to-submit preserved via native `<form>`. No custom keyboard handling introduced.
- Focus ring: all controls use `ring-ring` via shadcn defaults; no focus-ring suppression.
- Touch targets: 36px minimum on all buttons, inputs, select triggers, textareas, and radio items (shadcn default `h-9` or equivalent). Switch control is 36×20px; the surrounding label area extends the touch zone horizontally.

## Assumptions

- **A1.** `Field.Legend` is overridden to `font-semibold` (600) to respect Phase 11's "no weight 500" rule. If shadcn-svelte generates `Field.Legend` with hardcoded `font-medium`, the Marionette `FieldSet.svelte` overrides via `class="font-semibold"` on the legend or equivalent. No other typography overrides anticipated.
- **A2.** The shadcn-generated `Textarea`, `RadioGroup`, and `Switch` primitives use the same OKLCH tokens as existing shadcn primitives (verified via Phase 10 token system). No re-theming required.
- **A3.** `Field.Description` rendered at 14px `text-muted-foreground` (shadcn default) is acceptable as the Phase 14 "description" style; if the planner decides to enforce 12px consistently across description + error text, apply `class="text-xs"` uniformly on `Field.Description` and `Field.Error`. Either choice is valid as long as it's consistent across all six leaves. DEFAULT: keep shadcn's 14px for description, keep shadcn's 14px for error — they differ only in color. Planner may tighten to 12px during execution if visual density demands.
- **A4.** `crypto.randomUUID()` fallback for field `id` is available in all supported browsers (modern evergreen). If an older browser matrix is required, substitute `Math.random().toString(36)` — but current scope assumes modern.
- **A5.** The action row defaults to Option A (plain `Container class="flex gap-2 justify-end"`). Planner promotes to Option B (`FieldRow` SDUI component) only if a second consumer emerges within Phase 14. For Phase 14's scope (one contact form migration), Option A suffices.
- **A6.** `Form.svelte` children are wrapped in `Field.Group` with `space-y-6` for vertical rhythm. If the shadcn `Field.Group` primitive adds horizontal gap utilities that conflict with vertical stacking of sibling `FieldSet`s, replace with a plain `<div class="space-y-6">` without affecting the D-A3 "minor class tweak" scope.
