## Spacing Scale

Declared values (all multiples of 4; mapped to Tailwind utility classes — Tailwind 4's spacing scale `1 = 4px`):

| Token | Tailwind class | Pixel value | Catalog usage |
|-------|---------------|-------------|---------------|
| 1 | `p-1` / `gap-1` | 4px | Icon padding inside buttons; tight inline gaps |
| 2 | `p-2` / `gap-2` | 8px | Compact stack spacing inside Cards (e.g., legend ↔ content) |
| 3 | `p-3` / `gap-3` | 12px | Inner-grid cell gap (state matrix, button matrix) |
| 4 | `p-4` / `gap-4` | 16px | Card body internal vertical gap (heading → grid → interactive row) |
| 6 | `p-6` / `gap-6` | 24px | Card padding; outer Container vertical gap between Cards |
| 8 | `p-8` / `gap-8` | 32px | Placeholder mini-Cards padding (CAT-04 empty/loading/error) |

**Locked:**

- **Catalog screen root Container:** `class="flex flex-col gap-6 p-6"` (24px between Cards, 24px page padding all sides). Locks D-3-D outer-stack pattern.
- **Catalog Card emulation:** `class="rounded-lg border bg-card text-card-foreground shadow-sm p-6 flex flex-col gap-4"`. Locks RESEARCH.md Pattern 3 (Container-as-Card via class — NOT the `card: true` Container prop because that branch applies `max-w-md` and centers vertically, wrong for catalog).
- **Inner responsive grid:** `class="grid grid-cols-1 sm:grid-cols-N lg:grid-cols-M gap-3"` — 12px cell gap. N/M are per-screen below.
- **Mobile touch target minimum:** 44×44px for icon-only buttons. shadcn `size="icon"` is 32px (`size-8`); for catalog mobile usage, planner/executor MUST verify and either use `size="icon-lg"` (36px → still under 44px — borderline) or wrap icon buttons in a `min-h-11 min-w-11` Container on mobile. **Acceptance:** any icon-only button reachable on touch must be ≥44×44 in its tap-target. CAT-01 icon-only matrix cells are demos (not navigation), so the user only inspects them visually; the 44px minimum applies to actual interactive icon buttons in CAT-03 (DataTable Actions DropdownMenu trigger) and CAT-04 (modal close X). Verified that shadcn DropdownMenu trigger and Dialog close get sufficient padding via the existing components.

**Exceptions:** none — every spacing value used is on the 4-multiple scale.

## Typography

Catalog screens use shadcn-svelte's text scale verbatim (no per-screen overrides). Tailwind 4 `text-*` classes resolve to:

| Role | Tailwind class | Size | Weight | Line height | Catalog usage |
|------|---------------|------|--------|-------------|---------------|
| Body | `text-sm` | 14px | `font-normal` (400) | 1.43 (`leading-5`) | Default Text builder; intro paragraphs in each catalog screen; error message body; placeholder copy |
| Label | `text-xs` | 12px | `font-medium` (500) | 1.33 (`leading-4`) | Form `<Field.Label>`, Badge text, swatch labels, icon-name labels under icons |
| Heading 3 | `text-lg` | 18px | `font-semibold` (600) | 1.4 (`leading-7`) | Per-Card section headings ("variant = destructive", "TextInput", "Trigger surfaces") |
| Heading 1 | `text-2xl` | 24px | `font-bold` (700) | 1.33 (`leading-8`) | Catalog screen titles ("Buttons & Actions", "Forms", "Data Table", "Feedback", "Typography & Tokens") |

**Heading levels used per screen:**

- **CAT-01 Buttons:** H1 screen title; H3 per-variant card legend.
- **CAT-02 Forms:** H1 screen title; H2 per-input card heading ("TextInput", "Select", …); H3 reserved for explainer subheadings if any.
- **CAT-03 DataTable:** H1 screen title; no in-card headings (the DataTable header row plays that role).
- **CAT-04 Feedback:** H1 screen title; H2 per-card heading ("Trigger surfaces", "Placeholder states").
- **CAT-05 Typography:** H1 screen title; the **first card body** displays a full text-scale demo (H1, H2, H3, H4, H5, H6, body, label) using actual `Heading::level(N)` calls. H2 reserved for the other two cards ("Lucide icon catalog", "OKLCH semantic tokens").

**CAT-05 special notes:** Headings 4–6 are part of the demonstrated scale, not part of the chrome. All 6 levels MUST visibly differ in size/weight on screen so the demo communicates the scale. shadcn's default Heading.svelte uses `text-2xl`/`text-xl`/`text-lg`/`text-base`/`text-sm`/`text-xs` for levels 1–6 with descending weight; verify and document deviation if executor finds different.

**Line-height summary:** 1.4–1.5 across body/heading sizes (Tailwind defaults). No exceptions.

## Per-Screen Anatomy

### CAT-01 Buttons & Actions

**Outer layout (desktop ≥1024px):**

```
┌─ Container[class="flex flex-col gap-6 p-6"] ─────────────────────┐
│ H1: Buttons & Actions                                            │
│ Body Text: Every Button variant × size × state visible…          │
│                                                                  │
│ ┌─ Card 1: variant = default ──────────────────────────────────┐ │
│ │ H3: variant = default                                        │ │
│ │ ┌─ inner grid (lg:grid-cols-4) ──────────────────────────┐   │ │
│ │ │ [default/sm normal] [default/sm disabled] [default/sm  │   │ │
│ │ │  loading]            [default/sm icon]                 │   │ │
│ │ │ [default/md normal] [default/md disabled] …            │   │ │
│ │ │ [default/lg normal] [default/lg disabled] …            │   │ │
│ │ └────────────────────────────────────────────────────────┘   │ │
│ └──────────────────────────────────────────────────────────────┘ │
│ ┌─ Card 2: variant = destructive ──────────────────────────────┐ │
│ │ … same shape …                                               │ │
│ └──────────────────────────────────────────────────────────────┘ │
│ … 3 more Cards (outline, ghost, link) …                          │
└──────────────────────────────────────────────────────────────────┘
```

**Mobile layout (≤640px):** every inner-grid row collapses to a single column (`grid-cols-1`); cards still stack vertically. 5 Cards × 12 cells = 60 buttons stacked, scrollable.

**Inner grid responsive class:** `grid grid-cols-1 sm:grid-cols-4 lg:grid-cols-4 gap-3` (locked — 4 columns at sm and lg because there are exactly 4 states per (variant, size) row; the 3 sizes simply produce 3 grid rows).

**Cell anatomy:** each cell is a single Button with no extra chrome. Label is `<variant>/<size>` (e.g., `default/sm`). Loading state uses Loader2 icon spinning. Icon-only state uses `Plus` icon from registry with aria-label `<variant> <size> icon button`.

**Total cell count:** 5 variants × 3 sizes × 4 states = **60 buttons.**

**Interactions:**
- Click any non-disabled, non-loading cell → fires `gallery-demo/noop` → toast `Demo action: <variant>/<size>`.
- Disabled cells: no action, `cursor-not-allowed`, opacity 50%.
- Loading cells: no action, spinner visible.
- Icon-only cells: hover shows tooltip via aria-label (no shadcn Tooltip wrapping needed; aria-label is sufficient for screen readers).

```
│ Body Text: Every input × every state…                            │

│ │ <error slot — empty Container, replaced on invalid blur>     │ │
│ └──────────────────────────────────────────────────────────────┘ │
│ ┌─ Card 2: Select ─────────────────────────────────────────────┐ │
│ │ … same shape …                                               │ │

│ … 4 more Cards (Checkbox, Switch, Radio, Textarea) …             │
└──────────────────────────────────────────────────────────────────┘
```

**Mobile layout (≤640px):** state-grid collapses to single column (`grid-cols-1`). Each Card retains its FieldSeparator and interactive row.

**Inner grid responsive class:** `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-5 gap-3` (locked per CONTEXT.md D-3-D).

**State row composition (per Card):** 5 demonstration field instances, each with the appropriate state pre-applied:
- `Normal` — no flags.
- `Disabled` — `disabled(true)`.
- `With error` — has `/_errors/<bind>` seeded with the error message at render time.
- `Focused` — no special flag (focus is interactive); label says "click me" to invite focus.
- `With description` — `description(...)` set; renders below the input.

**Interactive row composition (per Card):**
- A FieldSeparator (visual divider between state-demo grid and live row).
- A single field with `bind` + a blur-action wired (`gallery-demo/catalog-forms/validate-<input>`).
- A pre-mounted **error slot** — empty Container at id `catalog-forms-<input>-error-slot`, ready for `set-node` / `set-children` / `delete-node` ops per D-3-C.

**ErrorDisplay (sibling-node) chrome:** when the error slot is filled with an ErrorDisplay node, it renders as:
```
[AlertCircle 16px destructive] Enter a valid email address.
```
Container class: `border-l-4 border-destructive bg-destructive/5 px-3 py-2 rounded flex items-center gap-2 text-sm text-destructive`.

**Phase 12 op assignment (locked per RESEARCH.md Pattern 7b — D-3-C didactic intent):**

| Card | Op on invalid blur | Op on valid blur | Notes |
|------|-------------------|------------------|-------|
| TextInput | `set-node` (insert ErrorDisplay) + `set-children` (add to card children) + data `set` to error path | `set-children` (remove from card children) + data `set` empty | TextInput exercises set-children; ErrorDisplay reads message from data store |
| Select | `set-node` (insert ErrorDisplay) + `set-children` | `delete-node` (remove ErrorDisplay) + data `set` empty | Select exercises delete-node |
| Checkbox | `set-node` (replace empty slot with Text/ErrorDisplay) + data `set` | `set-node` (replace slot back to empty Container) + data `set` empty | Checkbox exercises set-node |
| Switch | `set-node` (replace slot) + data `set` | `set-node` (replace slot back) + data `set` empty | Switch exercises set-node |
| Radio | `set-node` (insert ErrorDisplay) + `set-children` (add) + data `set` | `set-children` (remove) + data `set` empty | Radio exercises set-children |
| Textarea | `set-node` (insert ErrorDisplay) + `set-children` | `delete-node` (remove) + data `set` empty | Textarea exercises delete-node |

Each handler ALSO writes the error message to `/_errors/demo/catalog-forms/<bind>` via a parallel data `set` op so the ErrorDisplay component can read its message text from the data store. This is the only data-op write in CAT-02; it does not duplicate the visual error rendering (the field's own `<Field.Error>` is bypassed because the field's bind is on `/demo/catalog-forms/<input>-value`, not `/_errors/...`).

**State seeds for `seed_for_key("catalog-forms")`:** every state-demo field MUST be seeded so it renders correctly on first visit. Locked seed table:

| Bind path | Seeded value | Why |
|-----------|--------------|-----|

## Accessibility Checklist

Per-screen WCAG 2.1 AA + ARIA practices the catalog must satisfy. Validated by gsd-ui-checker dimension 2 (Visuals) + manual inspection during Chrome MCP UAT.

### CAT-01 Buttons & Actions

- [ ] Every Button has either visible text label OR `aria-label` (icon-only cells use `aria-label="<variant> <size> icon button"`).
- [ ] Disabled Buttons have `disabled` attribute (handled by builder); shadcn auto-applies `disabled:pointer-events-none disabled:opacity-50`.
- [ ] Loading Buttons announce loading state — Loader2 spinner is decorative (`aria-hidden`); Button keeps its label OR adds `aria-busy="true"` (verify Wave 0 Button polish does this; if not, add).
- [ ] Focus order: linear (top-to-bottom, left-to-right within each Card row).
- [ ] Focus indicator: shadcn `focus-visible:ring-ring/50 ring-3` (3px ring) — meets 3:1 contrast against any backdrop.
- [ ] Tap target: shadcn `size="default"` is 32px; `size="lg"` is 36px; `size="sm"` is 28px. **Mobile UAT note:** these are below WCAG 2.5.5 (44×44) minimum but acceptable for a catalog (which is a visual reference, not a workflow). Verify the gallery's actual interactive entry points (nav items, modal triggers, filter inputs) meet 44px elsewhere.

### CAT-02 Forms

- [ ] Every Field has `<Field.Label for={fieldId}>` — already wired in TextInput.svelte etc. (Phase 14 Field anatomy).
- [ ] Required fields have `required` attribute on the underlying input + visible "(required)" or `*` marker. CAT-02 catalog labels include "(required)" in the label text where relevant (Select, Checkbox, Switch, Radio interactive fields).
- [ ] Error messages render below the input. When using node-tree-op pathway (D-3-C), the sibling `ErrorDisplay` includes an `AlertCircle` icon + `text-destructive` color.
- [ ] **`aria-live` region** for validation errors: the ErrorDisplay component MUST render in an `aria-live="polite"` region so screen readers announce error appearance/disappearance on blur. **Action item for Wave 0 Form-polish OR catalog implementation:** verify `frontend/src/lib/components/feedback/ErrorDisplay.svelte` has `role="alert"` or `aria-live="polite"` on its root. If not, add it (single attribute change). Without this, the live-validation demo loses its accessibility story.
- [ ] **`aria-describedby`** wiring between Field.Description and the input: shadcn Field handles this if the markup pattern is followed; verify each form Svelte component sets `aria-describedby={descriptionId}` when description is present.
- [ ] **`aria-invalid`** on each input when error present: TextInput.svelte sets `aria-invalid={hasError || undefined}` (verified line 72). Other inputs MUST do the same — verify each Svelte component during Wave 0 form-polish review.
- [ ] Focus order: Card 1 (TextInput) → Card 2 (Select) → … → Card 6 (Textarea). Within each Card: state-grid fields → interactive field → (any error appears below interactive field).
- [ ] Tab into any interactive field, type, tab out → blur fires → error appears or clears within 200ms (server round-trip).
- [ ] Disabled fields are skipped by Tab navigation (shadcn handles this via `disabled` HTML attribute).
- [ ] Field labels have ≥4.5:1 contrast against `bg-card` (foreground on white = passes).

## Ambiguities Flagged + Locked

The CONTEXT.md flagged a few visual decisions to "Claude's discretion." This spec resolves each:

| Ambiguity | Decision (locked here) | Rationale |
|-----------|-------------------------|-----------|
| CAT-01: per-variant Cards OR per-size Cards | **Per-variant** (5 outer Cards) | Matches CAT-02's 6-Card cadence; inner 4-state row reads consistently. Per-size would yield 3 outer Cards × 5 variants × 4 states = 60 cells which is the same total but the visual rhythm is uneven (3 vs 5 vs 6 across catalogs). |
| CAT-04 placeholder side-by-side OR stacked | **Side-by-side at sm:+** (3-col grid); stacks at mobile | Matches the "individually triggerable + side-by-side" requirement in REQUIREMENTS.md CAT-04. |
| CAT-05 icon catalog: simple grid OR Accordion-categorized | **Simple grid** | The 14 registered icons don't warrant categorization. Accordion adds interaction overhead with no gain at this size. |
| CAT-05 swatches: grouped (base/sidebar/radius) OR flat | **Flat in declaration order** | Reading order matches `app.css` source order; designer can scan top-to-bottom against the file. |
| CAT-05 icon-cell affordance: Button-with-no-action OR plain Container | **Plain Container with icon + label** | Buttons-without-action are confusing; the catalog is a display, not interactive. |
| Status → Badge variant mapping | Active=default, Inactive=secondary, Pending=destructive | Pending = "needs attention" reads as destructive-ish; Active = primary positive (default); Inactive = neutral (secondary). |
| CAT-03 hidden-by-default columns | `status` + `actions` | Encourages user to discover the column-visibility toggle; the visible 5 columns (id, name, email, score, joined_at) are a clean "data" view. |
| Modal-close initial-focus target | shadcn Dialog default (first focusable inside) | Verify during UAT that destructive-confirm focuses Cancel, not Confirm — if not, log a Wave 0 micro-fix. |
