## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, input padding-y |
| md | 16px | Default element spacing, section padding |
| lg | 24px | Card padding, form group spacing |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Page-level vertical spacing |
| 3xl | 64px | Hero or full-page centering |

Exceptions: Touch targets on buttons use `h-10` (40px) per shadcn convention. This is Tailwind's `2.5rem` which maps to 40px at 16px base -- acceptable as a component height, not a spacing token.

**Source:** shadcn-svelte default; standard 8-point scale

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (normal) | 1.43 (20px) |
| Label | 14px (text-sm) | 500 (medium) | 1.43 (20px) |
| Heading | 20px (text-xl) | 600 (semibold) | 1.2 (24px) |
| Small / Helper | 12px (text-xs) | 400 (normal) | 1.33 (16px) |

**Rationale:** shadcn-svelte defaults to `text-sm` (14px) for body and form elements. This is a data-dense business app where 14px body maximizes information density while remaining legible. Labels at weight 500 provide sufficient contrast from body text. Only two effective weights are used: 400 (body/helper) and 500-600 (labels/headings).

**Source:** shadcn-svelte component conventions; RESEARCH.md stub patterns

## Color

All colors are OKLCH semantic tokens defined as CSS custom properties. Raw hex is not used -- values reference `var(--token-name)` which resolves to OKLCH at runtime.

### Light Mode (default)

| Role | Token | OKLCH Value | Usage |
|------|-------|-------------|-------|
| Dominant (60%) | `--background` | `oklch(1 0 0)` | Page background, main content area |
| Secondary (30%) | `--card` / `--muted` | `oklch(1 0 0)` / `oklch(0.967 0.001 286.375)` | Cards, sidebar background, table header, muted surfaces |
| Accent (10%) | `--primary` | `oklch(0.21 0.006 285.885)` | See reserved-for list below |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` | Delete buttons, error borders, error text |

### Dark Mode (tokens defined, toggle not wired)

| Role | Token | OKLCH Value |
|------|-------|-------------|
| Dominant | `--background` | `oklch(0.141 0.005 285.823)` |
| Secondary | `--card` / `--muted` | `oklch(0.21 0.006 285.885)` / `oklch(0.274 0.006 286.033)` |
| Accent | `--primary` | `oklch(0.92 0.004 286.32)` |
| Destructive | `--destructive` | `oklch(0.704 0.191 22.216)` |

### Accent Reserved For

The `--primary` / `bg-primary text-primary-foreground` combination is reserved exclusively for:

1. Primary action buttons (Submit, Save, Confirm)
2. Active navigation item indicator
3. Focus ring color (`--ring`)
4. Primary CTA in empty states (future phases)

All other interactive elements use `--secondary` or `--accent` (hover states on table rows, sidebar items, dropdowns).

### Semantic Token Map (Flowbite to shadcn)

Stubs MUST use semantic tokens, never raw Tailwind colors:

| Old (Flowbite/raw) | New (shadcn semantic) |
|---------------------|----------------------|
| `bg-white` | `bg-background` |
| `bg-gray-50`, `bg-gray-100` | `bg-muted` |
| `text-gray-500`, `text-gray-600` | `text-muted-foreground` |
| `text-gray-700`, `text-gray-900` | `text-foreground` |
| `border-gray-200` | `border-border` |
| `bg-red-50` | `bg-destructive/10` |
| `text-red-600` | `text-destructive` |
| `hover:bg-gray-50`, `hover:bg-gray-100` | `hover:bg-accent` |

### Surface.svelte Layout Classes

| Surface type | Old classes | New classes |
|-------------|------------|------------|
| main | `bg-white` | `bg-background` |
| sidebar | `bg-gray-50 border-r border-gray-200` | `bg-sidebar-background border-r border-sidebar-border` |

## Copywriting Contract

This phase creates no new user-facing screens. Stubs preserve existing copy from the SDUI protocol (server-driven labels). The copywriting contract covers only the stub-internal fallback text:

| Element | Copy |
|---------|------|
| Button fallback label | (empty string -- label comes from `props.label`) |
| Error field message | `{fieldError}` (server-provided, displayed as-is) |
| Helper text | `{props.helperText}` (server-provided, displayed as-is) |
| Connection banner | "Connecting..." (existing copy, preserved in stub) |
| Error boundary heading | "Something went wrong" (existing copy, preserved in stub) |
| Error boundary body | "An error occurred while rendering this component." (existing copy, preserved in stub) |

**No new CTA, empty state, or destructive action copy is needed for this phase.** All user-facing text is server-driven via the SDUI protocol.

**Source:** RESEARCH.md Code Examples; existing component source

## Interaction Contract

### Stub Behavior Requirements

Every stub MUST preserve the full SDUI interface contract. These interaction patterns are non-negotiable:

| Pattern | Requirement |
|---------|-------------|
| Data binding | Stubs with `bind` prop MUST read via `getData()` and write via `setData()` on input events |
| Actions | Stubs with `action` prop MUST call `sendAction()` on the appropriate event (click, blur, etc.) |
| Dirty tracking | Form field stubs MUST call `markDirty()` on focus and `clearDirty()` on blur |
| Error display | Form field stubs MUST read `/_errors{bind}` path and display error state |
| Disabled state | All interactive stubs MUST respect `props.disabled` with `opacity-50 pointer-events-none` |

### Component Stub Visual Contract

| Component | Required Visual Elements |
|-----------|------------------------|
| Button | `<button>` with `rounded-md text-sm font-medium h-10 px-4 py-2`; three variants: primary (`bg-primary`), outline (`border border-input bg-background`), destructive (`bg-destructive`) |
| TextInput | `<input>` with `h-10 rounded-md border border-input bg-background px-3 py-2 text-sm`; focus ring: `focus-visible:ring-2 focus-visible:ring-ring`; error state: `border-destructive` |
| SelectInput | `<select>` with same dimensions and border treatment as TextInput |
| Checkbox | `<input type="checkbox">` with inline label |
| Spinner | SVG circle with `animate-spin` class, `size-6` default |
| Container (Card) | `<div>` with `rounded-lg border border-border bg-card p-6 shadow-sm` |
| Modal | Fixed overlay `bg-black/50` + centered `bg-background rounded-lg shadow-lg` dialog; close on backdrop click |
| Toast | Positioned `<div>` with `border rounded-md p-4 shadow-md`; dismiss button |
| Alert/ErrorDisplay | `<div>` with `bg-destructive/10 text-destructive border border-destructive/20 rounded-md p-4` |
| SideNav | `<nav>` wrapper; items are `<button>` or `<a>` with `hover:bg-accent rounded-md px-3 py-2`; active state: `bg-accent text-accent-foreground font-medium` |

**Source:** RESEARCH.md Code Examples and Flowbite Import Inventory

## Border Radius

| Token | Value | Derived From |
|-------|-------|-------------|
| `--radius` | `0.25rem` (4px) | CONTEXT.md D-02 |
| `--radius-sm` | `0.125rem` (2px) | `calc(var(--radius) - 0.125rem)` |
| `--radius-md` | `0.25rem` (4px) | `var(--radius)` |
| `--radius-lg` | `0.375rem` (6px) | `calc(var(--radius) + 0.125rem)` |
| `--radius-xl` | `0.5rem` (8px) | `calc(var(--radius) + 0.25rem)` |

Usage: Buttons and inputs use `rounded-md`. Cards use `rounded-lg`. Badges and small elements use `rounded-sm`.
