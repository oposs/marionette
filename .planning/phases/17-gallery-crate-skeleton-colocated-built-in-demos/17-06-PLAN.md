See PROJECT.md blockers: "AppShell nestability unknown" — this is the first observed instance.

**Options considered** (VERIFICATION.md G-02 §Fix scope):
- (a) Rewrite `AppShell::gallery_demo()` to render a plain Container layout that SIMULATES the AppShell structure (inline divs with headings) — no SurfaceMount, no nested AppShell builder, no Sidebar.Provider collision. **Chosen — matches pre-deployment posture (fix root cause), doesn't punt to Phase 19, keeps the demo visually informative.**
- (b) Render only a Text+Heading description ("An AppShell has slots for sidebar/header/main/...") — too bland.
- (c) Introduce frontend-scoped surface names — framework change, Phase 19 concern.

**G-05 root cause confirmed during planning — specific to each of the 5 components:**

1. **error-display.rs** — ErrorDisplay.svelte (frontend/src/lib/components/feedback/ErrorDisplay.svelte) renders nothing unless `errors = getData(surface, bind)` returns a non-empty array. The demo sets `.message("Example error message")` (an unused Rust prop — ErrorDisplay has no `message` prop on the frontend). Fix: demo must `.bind("/demo/error-display/errors")` AND seed_for_key must populate that path with `[{path: "/x", message: "..."}, ...]`.

2. **field-set.rs / radio-group.rs / switch.rs / textarea.rs** — these 4 share a SUSPECTED common root cause. Static analysis suggests the demo bodies are structurally correct (Container wrapping component instances, mirroring the working Button/Checkbox/Heading/TextInput pattern). Chrome MCP UAT saw them as empty. Need to investigate WITH LIVE SERVER — Task 2 drives Chrome MCP + wire inspection to diagnose, then Task 3 applies the fix. Plausible hypotheses (ordered by likelihood):
   - **H1 — Missing seed data** for bind paths the frontend components require (Switch reads `checked` from bind; Textarea reads `value` from bind; RadioGroup reads value from bind; an unseeded bind makes the component's `$derived` return `undefined` and MAY cause the Field wrapper to fail-silent). VERY LIKELY for Switch/Textarea/RadioGroup. Note: seed_for_key in show.rs does have entries for these but uses a different sub-path than the bind in the demo body (e.g. demo binds `/demo/switch/checked-1` but seed creates `/demo/switch/checked`).
   - **H2 — Bind path typo** — the demo body's `.bind("...")` path doesn't match seed_for_key's emitted path.
   - **H3 — Frontend component throws on missing required prop** — e.g. RadioGroup's `options` array, which IS provided. Unlikely but possible if serialization strips the field.
   - **H4 — Field.Field wrapper invisibility** when data doesn't flow — the `data-invalid` / `aria-invalid` state may force a display:none in some Tailwind class combination (unlikely).

        use crate::builders::heading::Heading;

            .id("demo-app-shell-header-content").build();
        let header_box = Container::new()
            .id("demo-app-shell-header-box")
            .children(vec![header_label, header_content])
            .build_with_children();

        // ---- Main slot (static representation) ----
        let main_label = Heading::new("Main slot").id("demo-app-shell-main-label").level(3).build();
        let main_content = Text::new(

            .children(outer_children)

        all.extend(sidebar_box.into_iter().skip(1));

        all.extend(main_box.into_iter().skip(1));
        all.extend(footer_box.into_iter().skip(1));
        all.extend(popups_box.into_iter().skip(1));
        all
    }
