<objective>
Close the five handler-layer / sub-surface gaps surfaced by Phase 17 UAT (G-01, G-03, G-04, G-06, G-07).

All five gaps share the backend `gallery-demo/src/handlers/*.rs` layer plus one tightly-scoped frontend close-semantics touch on `ModalSurface.svelte`. Plan 17-06 (sibling, Wave 1) owns demo-body fixes (G-02, G-05).

**Root causes identified during planning (see PLAN investigation notes):**

1. **G-01 Modal lockup** — `handle_modal_open` currently renders a `Modal::new(...)` component (serialized as `type: "modal"`) into the `modal` sub-surface. The frontend registry maps `"modal"` → `ModalSurface.svelte`, which itself reads `getSurfaceTree('modal')`. NodeRenderer tries to render the modal tree's root, resolves `type: "modal"` → a second `ModalSurface`, which reads `getSurfaceTree('modal')` again → infinite reactive recursion → tab lockup. (Confirmed by `grep "'modal': ModalSurface" frontend/src/lib/registry/defaults.ts`.)

2. **G-04 ConfirmDialog doesn't dismiss** — ModalSurface.svelte computes `isOpen = $derived(tree !== undefined)`. Once any Render lands on the `modal` sub-surface, `setSurfaceTree` creates the tree and `isOpen` stays `true` forever. The existing `handle_confirm_accept/reject` handlers ARE rendering an empty Container to clear the modal, but `tree` still exists (it's the Container), so `isOpen` stays `true`. Fix: change `isOpen` to also return `false` when the tree's root is an empty Container (the canonical "closed" sentinel already emitted by the backend).

3. **G-06 Home footer oversized** — `navigate.rs:51,54` uses `Heading::new(...)` for the footer version + connection-status lines. Heading renders as `<h2 class="text-xl font-semibold">`, overriding the footer wrapper's `text-xs text-muted-foreground`. Change to `Text::new(...)` (same pattern CRM uses).

4. **G-07 Modal sub-surface unseeded** — `navigate.rs` currently seeds `toasts` with an empty Container (good — matches CRM pattern at crm-demo/src/main.rs:302-309), but does NOT seed `modal`. An unseeded sub-surface's `SurfaceMount` renders a LoadingSkeleton placeholder (visible as the grey bars below the footer). Add a 4th Render for `modal` with an empty Container root, mirroring the toasts seed.

5. **G-03 DataTable empty** — `show.rs::seed_for_key("data-table")` embeds rows under `/demo/data-table/rows`, but the DataTable demo carries `source = "demo-rows"` and the frontend DataTable issues a `fetch-rows` action on mount, NOT a data-store read. The handler `handle_demo_fetch_rows` exists but is only invoked when the frontend requests rows. Root-cause fix: `handle_demo_fetch_rows` already returns the right rows — the issue is that the Patch operations use `Set { path: /demo/data-table/rows/{row_id}, ... }`, which creates an *object* keyed by row_id, not an *array*. Frontend DataTable expects an array. Fix: return rows as a single `Set` op with `path: /demo/data-table/rows` and the full array value (or use the canonical row-array shape verified by the working CRM contact_list → content surface contract).

Purpose: Phase 17 SC #5 ("every nav entry produces a screen, not an error surface") closes for 5 of the 7 gaps.
Output: Four modified backend files + one modified frontend file + a rebuilt frontend bundle.
