# Phase 12 Plan 01: Scaffolding Summary

**One-liner:** Installed shadcn-svelte Sidebar + Sonner primitives, renamed the `--sidebar-background` token to the canonical `--sidebar` shadcn name, and seeded empty compilable placeholders for every file Waves 1-3 will edit.

## What Shipped

### Task 1 — shadcn primitive install

- `npx shadcn-svelte@latest add sidebar` installed the Sidebar block into `frontend/src/lib/components/ui/sidebar/` (26 files): Provider, Trigger, Rail, Inset, Sidebar shell, Header/Footer/Content, Group (label/content/action), Separator, Input, plus Menu primitives (menu/menu-item/menu-button/menu-action/menu-badge/menu-skeleton) and sub-menu variants.
- Sidebar block pulled Sheet (11 files) and Tooltip (6 files) as transitive dependencies — these are required for responsive collapse into a sheet drawer and for icon-only collapsed-state labels.
- `is-mobile.svelte.ts` hook was added under `src/lib/hooks/` (installer-provided, required by Sidebar for breakpoint detection).
- `npx shadcn-svelte@latest add sonner` installed `frontend/src/lib/components/ui/sonner/` (index.ts + sonner.svelte) and added `svelte-sonner ^1.1.0` + `mode-watcher ^1.1.0` to `package.json` devDependencies.
- shadcn-svelte CLI version: **1.2.7** (installed on the fly via `npx`).
- The installer did **not** modify `src/app.css` — the existing `--sidebar-*` tokens remained in place for Task 2 to handle, which is why the installer's overwrite prompts were all declined.

**Pitfall 1 (RESEARCH.md token trap) discovery:** The installer fetched the Sidebar components that internally use `bg-sidebar` (no `-background` suffix), confirming the token name the plan predicted.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Added missing `WithoutChild` / `WithoutChildrenOrChild` type helpers to `lib/utils.ts`**

- **Found during:** Task 1 (immediately after `shadcn-svelte add sidebar`).
- **Issue:** `npm run check` reported 11 errors of the form `'"$lib/utils.js"' has no exported member named 'WithoutChild'` across the newly installed `sheet-content.svelte`, `tooltip-content.svelte`, `sidebar-menu-button.svelte`, AND the pre-existing Phase 10 checkbox / dialog / select shells. The Phase 10 stubs had been referencing these helpers all along; the helpers were simply never added to `lib/utils.ts`. The new shadcn installs surfaced this as a hard error.
- **Fix:** Added the two type helpers (one-line Omit wrappers) inline, matching the canonical shadcn-svelte registry shape.
- **Files modified:** `frontend/src/lib/utils.ts`
- **Commit:** `bf1485b`
- **Side effect (positive):** Resolved the pre-existing Phase 10 checkbox/dialog/select type errors as a happy accident.

**2. [Rule 3 — Blocking] `npm install` before running shadcn-svelte installer**

- **Found during:** Task 1 (first `npx shadcn-svelte add sidebar` invocation).
- **Issue:** The worktree was fresh — `frontend/node_modules` did not exist, so `shadcn-svelte` CLI's internal `npx svelte-kit sync` step failed with `Process exited with non-zero status (1)`.
- **Fix:** Ran `npm install` (30 seconds, 290 packages) before retrying the shadcn installer.
- **Files modified:** none (side effect of installer run).
- **Commit:** n/a (pre-install step).

**3. [Rule 1 — Warnings] Reworked scaffold `$props()` shape to silence `state_referenced_locally` warnings**

- **Found during:** Task 3 (`npm run check` after initial scaffold commit would have been clean but svelte-check emitted 8 warnings).
- **Issue:** The original scaffold pattern from the plan text destructured each prop and used `void props; void bind; void action; void surface;` to mark them unused. svelte-check warned that reading reactive props at the top of `<script>` "only captures the initial value" (state_referenced_locally).
- **Fix:** Replaced the `void`-discard pattern with a single unused typed binding `let _props: {...} = $props()` plus an `eslint-disable-next-line @typescript-eslint/no-unused-vars` comment. This keeps the scaffold type-safe for Plan 06 to reference later while silencing svelte-check.
- **Files modified:** `AppShell.svelte`, `SurfaceMount.svelte`
- **Commit:** `302214f`

No authentication gates, no architectural changes, no Rule 4 escalations.
