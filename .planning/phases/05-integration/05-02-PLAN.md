**3. Create frontend/tests/helpers/ws-capture.ts:**

Export a `captureWebSocketFrames` function that takes a Playwright `Page` and returns a reference to a growing array of captured frames:

```typescript
import type { Page } from '@playwright/test';

export interface CapturedFrame {
  direction: 'sent' | 'received';
  data: Record<string, unknown>;
  timestamp: number;
}

export function captureWebSocketFrames(page: Page): CapturedFrame[] {
  const frames: CapturedFrame[] = [];
  page.on('websocket', (ws) => {
    ws.on('framesent', (frame) => {
      try {
        frames.push({
          direction: 'sent',
          data: JSON.parse(frame.payload as string),
          timestamp: Date.now(),
        });
      } catch { /* binary frame, skip */ }
    });
    ws.on('framereceived', (frame) => {
      try {
        frames.push({
          direction: 'received',
          data: JSON.parse(frame.payload as string),
          timestamp: Date.now(),
        });
      } catch { /* binary frame, skip */ }
    });
  });
  return frames;
}
```

**CRITICAL**: The listener MUST be registered BEFORE `page.goto()` to capture the initial WebSocket connection frames (Pitfall 6 from research).

**4. Create frontend/tests/helpers/schema-validator.ts:**

Build an AJV-based validator that loads the OpenAPI YAML schemas and validates messages:

- Load all 4 YAML files from `spec/schemas/` using `js-yaml` and `fs.readFileSync`
- Use `path.resolve(__dirname, '../../../spec/schemas')` for the path
- Build a combined definitions object by merging all top-level type definitions from each YAML file into a flat `$defs` map
- Rewrite cross-file `$ref` values (like `"data.yaml#/PatchOperation"`) to internal format (`"#/$defs/PatchOperation"`)
- Create an AJV instance with `{ allErrors: true, strict: false }`, register formats via `addFormats`
- Export `createValidator()` which returns an object with methods:
  - `validateRender(msg: unknown): boolean` - validates against RenderMessage schema
  - `validatePatch(msg: unknown): boolean` - validates against PatchMessage schema
  - `validateHello(msg: unknown): boolean` - validates against HelloMessage schema
  - `validateAction(msg: unknown): boolean` - validates against ActionMessage schema
  - `getErrors(): string | null` - returns human-readable error string or null

The schema files define types at the top level (not nested under `components/schemas`). For example, `message.yaml` has `RenderMessage`, `PatchMessage`, etc. at the root. Each type is a full JSON Schema object.

Handle the cross-file $ref resolution pragmatically: load each YAML file, iterate all `$ref` values recursively, and rewrite `"filename.yaml#/TypeName"` to `"#/$defs/TypeName"`. Then register the merged schema with all types under `$defs`.

If AJV cross-file ref resolution proves too complex, fall back to a simpler approach: validate only the structural shape (type field present, required fields present) without full schema validation, and add a TODO comment noting the limitation.
