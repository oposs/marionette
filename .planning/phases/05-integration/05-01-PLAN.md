**1. Fix handle_text_message in ws.rs (Pitfall 3 from research):**

The frontend sends `{ type: 'hello', version: '1.0.0' }` on WebSocket open (websocket.svelte.ts line 25). Currently `handle_text_message` tries to parse ALL text as `ActionMessage`, which will fail for hello messages.

Fix: Before trying to parse as `ActionMessage`, first parse as generic `serde_json::Value`, check the `"type"` field. If `type` is `"action"`, parse as `ActionMessage` and dispatch. If `type` is `"hello"`, log it and silently acknowledge (no response needed -- server already sent its own hello). For any other type, send an error response about unexpected message type.

Specifically in `handle_text_message`:
```rust
// Parse as generic JSON first
let value: serde_json::Value = match serde_json::from_str(text) {
    Ok(v) => v,
    Err(e) => {
        // Send parse error...
        return;
    }
};

// Check message type
let msg_type = value.get("type").and_then(|t| t.as_str()).unwrap_or("");
match msg_type {
    "action" => {
        // Parse as ActionMessage and dispatch (existing logic)
        let action: ActionMessage = match serde_json::from_value(value) { ... };
        // ... dispatch ...
    }
    "hello" => {
        debug!(session_id = %session.id, "Received client hello, acknowledging");
        // No response needed -- server already sent its hello
    }
    other => {
        let error_msg = ProtocolMessage::Error(ErrorMessage {
            id: None,
            errors: vec![ValidationError {
                path: None,
                message: format!("Unexpected message type: {other}"),
            }],
        });
        let _ = tx.send(error_msg).await;
    }
}
```
