    /// Build one observation-matrix cell: dimension heading + badge + findings Text.
    /// Findings Text is bound to a data path so the frontend probe can overwrite it.
    fn build_matrix_cell(
        id: &str,
        dimension_name: &str,
        cell_class: &str,
        icon_name: &str,
        badge_text: &str,
        badge_variant: &str,
        findings_bind: &str,
    ) -> (Node, Vec<Node>) {
        let dim_heading = Heading::new(dimension_name)
            .id(&format!("{id}-heading")).level(3).build();
        let badge = Badge::new(badge_text)
            .id(&format!("{id}-badge"))

            .icon(icon_name)

            .build();

            .id(id)
            .class(cell_class)
            .children(vec![dim_heading, badge, findings])
            .build_tree()
    }

    # Scoped surface-name framework extension for nested AppShell

    ## Problem

    Nesting an `AppShell` inside another `AppShell`'s content slot causes
    `<Sidebar.Provider>` context collision. Observed 2026-04-22 in Phase 17 G-02
    and re-surfaced with live evidence by Phase 19 EXER-01.

    Root cause: `frontend/src/lib/components/ui/sidebar/context.svelte.ts:62`
    stores the sidebar state under the global key `Symbol.for("scn-sidebar")`.
    When a second `Sidebar.Provider` mounts, `setContext(Symbol.for("scn-sidebar"), innerState)`
    shadows the outer provider for the entire inner subtree — but the inner
    `Sidebar.Root` renders at the same viewport anchors as the outer (both target
    the layout-root viewport), visually replacing the outer 20-entry nav with
    the inner 3-entry nav.

    The same collision propagates to:
    - `--sidebar-*` CSS custom properties (inheritance cascades from outer to
      inner; no scoping mechanism).
    - Mobile Sheet overlay (both providers construct their own `new IsMobile()`
      and render a Sheet; dismiss cascades).
    - Keyboard shortcut (`Ctrl+B` by default per
      `frontend/src/lib/components/ui/sidebar/constants.ts:6`): the global
      `<svelte:window onkeydown>` listener fires for BOTH providers; last-
      registered wins non-deterministically.

    EXER-01's observation matrix captures all four dimensions live and ships
    the findings alongside the broken-nesting screen.

    ## Proposed scope

    Introduce a **scoped-surface-name** framework extension that threads a
    `surface_name: &'static str` through the `AppShell` builder and down to
    `Sidebar.Provider`:

    1. **Builder API (backend):** `AppShell::new().surface_name("inner")` sets
       a `data-surface="inner"` attribute on the root shell element.

    2. **Svelte component (frontend):** `<Sidebar.Provider surfaceName?>`
       accepts an optional key; falls back to `"default"` if unset. Replaces
       the global `Symbol.for("scn-sidebar")` with per-surface keys:
       `Symbol.for(\`scn-sidebar-\${surfaceName}\`)`. `getContext` calls look
       up their specific key.

    3. **CSS scoping:** shadcn sidebar tokens resolve via
       `:where([data-surface="<name>"]) { --sidebar-*: ... }` so the inner
       shell's tokens do not inherit outer values. Use `@scope` where widely
       supported; fall back to `:where()` selector scoping otherwise.

    4. **Mobile sheet:** each `Sidebar.Provider` owns its own Sheet mount
       under a surface-named portal (e.g. `#sheet-portal-<surface_name>`).
       Dismiss events are scoped to the triggering surface.

    5. **Keyboard shortcut scoping:** `<svelte:window onkeydown>` listeners
