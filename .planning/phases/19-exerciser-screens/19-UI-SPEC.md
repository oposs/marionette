# Phase 19 — UI Design Contract

> Visual and interaction contract for the three exerciser screens (EXER-01 Nested AppShell, EXER-02 Rapid Patching, EXER-03 Pathological Scale). Generated by gsd-ui-researcher; consumed by gsd-planner, gsd-executor, gsd-ui-checker, and gsd-ui-auditor.
>
> **Context inheritance.** Phase 19 inherits its design system wholesale from Phase 18 (`.planning/phases/18-catalog-screens/18-UI-SPEC.md`). Spacing scale, typography scale, colour tokens, CTA copy patterns, icon contract, shadcn-svelte preset, font stack are unchanged. This spec lists exerciser-specific decisions (observation matrix layout, cadence control widget, invariant status lights, perf readout banner, 80-field form grouping) and reiterates the inherited defaults in the required template sections so downstream checkers (gsd-ui-checker) can validate the 6 dimensions without chasing cross-references.
>
> **Locked per CONTEXT.md D-1..D-4:**
> - D-1: EXER-01 ships broken-nesting evidence + v1.3 framework-extension seed proposal (no v1.2 fix).
> - D-2: EXER-02 exercises all 4 invariants (focus, cursor, typed input, IME).
> - D-3: EXER-03 captures 4 perf signals (TTFP, scroll FPS, memory, patch latency) as advisory soft thresholds.
> - D-4: Findings default to v1.3 seed deferral; trivial fixes (<30min, no scope creep, no new deps) allowed inline.

## Spacing Scale

Inherited verbatim from Phase 18 (Tailwind 4's `1 = 4px` scale):

| Token | Tailwind class | Pixel value | Exerciser usage |
|-------|---------------|-------------|-----------------|
| 1 | `p-1` / `gap-1` | 4px | Icon padding inside badges; tight inline gaps in status lights |
| 2 | `p-2` / `gap-2` | 8px | Compact stack spacing inside Cards; cadence RadioGroup option spacing |
| 3 | `p-3` / `gap-3` | 12px | Inner-grid cell gap (observation matrix, invariant dashboard, perf banner) |
| 4 | `p-4` / `gap-4` | 16px | Card body internal vertical gap; field stack within FieldSet groups (EXER-03) |
| 6 | `p-6` / `gap-6` | 24px | Card padding; outer Container vertical gap between Cards |
| 8 | `p-8` / `gap-8` | 32px | Nested-AppShell inner content padding (EXER-01 inner shell's content slot) |

**Locked exerciser-specific patterns:**

- **Exerciser screen root Container:** `class="flex flex-col gap-6 p-6"` (identical to Phase 18 catalog root). Locks vertical rhythm.
- **Card emulation:** `class="rounded-lg border bg-card text-card-foreground shadow-sm p-6 flex flex-col gap-4"` (Pattern 3 from Phase 18 RESEARCH.md; NOT the `card: true` Container prop).
- **EXER-01 observation matrix grid:** `class="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 gap-3"` — 4 columns at desktop (one per dimension: provider context, mobile sheet, keyboard shortcuts, `--sidebar-*` tokens).
- **EXER-02 invariant dashboard grid:** `class="grid grid-cols-2 sm:grid-cols-2 lg:grid-cols-4 gap-3"` — 4 columns at desktop, 2×2 at mobile (one cell per invariant: focus, cursor, typed input, IME). Always 2+ wide — NEVER collapse to `grid-cols-1` because the 4-light readout loses its dashboard feel when stacked.
- **EXER-03 perf banner grid:** `class="grid grid-cols-2 sm:grid-cols-2 lg:grid-cols-4 gap-3"` — 4 columns at desktop, 2×2 at mobile (one cell per signal: TTFP, FPS, Memory, Patch latency).
- **EXER-03 80-field FormScreen inner grouping:** 4 FieldSet groups × 20 fields each. FieldSet layout `cols=2` at desktop (10 rows × 2 columns), `cols=1` at mobile. FieldSeparator between groups.
- **Mobile touch target minimum:** 44×44px for EXER-02 Play/Pause/Reset CTAs (interactive) — wrap icon buttons in `min-h-11 min-w-11` Container OR use `size="lg"` (40px) + `px-4 py-2` padding (total ≥44px). EXER-01/EXER-03 have no icon-only interactive buttons on mobile so the minimum only applies to the single EXER-02 cadence control row.

**Exceptions:** none — every spacing value used is on the 4-multiple scale.

**Interactions:**
- User types in Focused input → keystrokes flow to `/demo/exer-02/focused-value` via standard SDUI data op.
- User picks cadence → RadioGroup change → writes to `/demo/exer-02/cadence-ms`. If patching is already active, new cadence applies on the next tick.
- `Start patching` → backend begins a patch loop targeting `/demo/exer-02/patch-sink/<iter>` at chosen cadence. Each tick fires: set-node, delete-node, or set-children (rotate through the 3 op kinds to exercise all patch types). Frontend invariant-watch code (in a small new exerciser helper file) observes focus, cursor, typed-value diff, and IME `compositionstart`/`compositionend` events and updates invariant badges via set-node patches to the dashboard cells.
- `Pause patching` → stops the loop; invariants freeze at their current state; elapsed timer pauses.
- `Reset counters` → clears patch log (emits delete-node for each row), resets invariant badges to PENDING, resets elapsed to 0.
- Patch log entries: append via `set-children` on the log Container; when over 200 rows, delete the oldest via `delete-node`.

**60-second passing criterion:** an invariant that shows PASS for 60 continuous seconds at the `Default (500 ms)` cadence is the locked success threshold (PATCH-02 invariant). The UI does not declare "passed" automatically — the phase verifier runs the test manually, observes, and records.

**Perf measurement mechanics (frontend responsibility).** The 4 readouts are captured by frontend instrumentation in a small new file (e.g., `frontend/src/lib/exer03/perf.ts`):
- **TTFP:** `performance.getEntriesByType('paint')[0].startTime` at mount time.
- **Scroll FPS:** requestAnimationFrame delta measurement during a 5-second window triggered on first scroll or on Remeasure.
- **Memory:** `performance.memory.usedJSHeapSize` snapshot at mount + snapshot at mount+30s.
- **Patch latency:** frontend PatchHandler middleware records the Δt between PatchMessage receive and apply-complete; exposes p95 over a rolling window of the last 100 patches.

Readouts update by patching `/demo/exer-03/perf/{ttfp,fps,memory,latency}` from the frontend via an action send — this is an intentional "frontend initiates a patch to itself via the backend" round-trip that exercises the PatchMessage pipeline in the direction no other gallery screen uses.
