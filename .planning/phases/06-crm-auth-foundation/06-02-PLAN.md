**1. Add to `handlers/user.rs`:**

**`handle_user_form`** -- renders create/edit form:
- Extract optional `Payload<UserIdPayload>` -- if payload has `user_id`, this is an edit; otherwise, create
- For edit: fetch user from DB, pre-fill form data
- Build Form with:
  - TextInput(label="Name", bind="/userForm/name")
  - TextInput(label="Email", bind="/userForm/email")
  - TextInput(label="Password", bind="/userForm/password") -- empty for edit (leave unchanged if blank)
  - Select(label="Role", bind="/userForm/role", options=[("admin","Admin"), ("user","User")])
  - Hidden field or data for user_id (if editing): include in form data as `/userForm/id`
  - Button("Save", action=submit("user_save"))
  - Button("Cancel", action=click("user_list"))
- Data: `{"userForm": {"id": null|N, "name": "...", "email": "...", "password": "", "role": "user"}}`
- Return RenderMessage with surface "main", root "user-form-root"

Also handle `handle_user_new` as a simple alias that calls `handle_user_form` with no payload (or register the same handler).

**`handle_user_save`** -- creates or updates user:
- Extract `Payload<UserSavePayload>` with `#[derive(Deserialize)] struct UserSavePayload { id: Option<i32>, name: String, email: String, password: String, role: String }`
- Validate: name non-empty, email non-empty, role is "admin" or "user"
- If `id` is None (create):
  - Validate password length >= 8 chars, return `ActionError::BadPayload` if too short
  - Hash password with bcrypt cost 10 via `tokio::task::spawn_blocking`
  - Insert new user entity
- If `id` is Some (update):
  - Fetch existing user, return error if not found
  - Update name, email, role
  - If password is non-empty, hash and update; otherwise keep existing hash
  - Save via `user::ActiveModel` with `Set()` values
- After save, re-render the user list (call the shared `render_user_list` helper)
