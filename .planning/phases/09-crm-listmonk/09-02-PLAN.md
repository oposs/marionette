   NOTE: The executor MUST read `backend/crates/marionette/src/ws.rs` and `backend/crates/marionette/src/extractors.rs` to understand how HandlerContext is constructed and what fields it has. The listmonk client needs to be accessible from within handlers. Options:

   - If not, add a field to HandlerContext for optional extensions (similar to AppState.listmonk).
   - Alternatively, store the ListmonkClient in a `once_cell::sync::OnceCell<Arc<ListmonkClient>>` static that gets initialized in main.rs.

   Choose the approach that requires the least modification to the marionette library crate. A `once_cell` / `std::sync::OnceLock` static in the crm-demo crate is the simplest option if HandlerContext doesn't support extensions.

   **Core sync function `sync_one_contact`:**
   ```rust
   pub async fn sync_one_contact(
       client: &ListmonkClient,
       db: &sea_orm::DatabaseConnection,
       contact: &contact::Model,
       tags: &[String],
   ) -> Result<i32, String> {
       // 1. For each tag name, call client.get_or_create_list(tag_name) to get list IDs
       // 2. Check if subscriber exists: client.find_subscriber_by_email(&contact.contact_email)
       // 3. If exists: client.update_subscriber(id, email, name) then set_subscriber_lists
       // 4. If not: client.create_subscriber(email, name, list_ids)
       // 5. Record success in listmonk_sync table (upsert: delete old + insert new)
       // 6. Return subscriber_id
   }
   ```
   On error, catch the error string and record it in listmonk_sync with status "error".

   **`handle_listmonk_sync` (single contact sync):**
   - Deserialize payload: `{ contact_id: i32 }`
   - Load contact from DB
   - Load contact's tags (via contact_tag + tag entities)
   - Get ListmonkClient (via OnceLock or whichever mechanism)
   - If client is None, return ActionError::Internal("Listmonk is not configured")
   - Call `sync_one_contact`
   - After sync, re-render the contact form (same pattern as `handle_contact_tag_save` -- construct a new HandlerContext with contact_id payload and call `handle_contact_form`)

   **`handle_listmonk_sync_all` (bulk sync):**
   - Load all contacts that have a non-empty email
   - For each contact, load tags and call `sync_one_contact`
   - Collect results: count successes and failures
   - After all syncs, re-render the contact list with a summary message
   - Return the contact list render (call `handle_contact_list`)
